# Overreach — Pace & Load Agent

A personal running dashboard that pulls your runs from Strava (e.g. synced from Runna), computes acute-vs-chronic training load, and tells you exactly when to cut back or ramp up — then writes a narrative weekly log.

Built with Next.js and bootstrapped with [v0](https://v0.app). Deployed on Vercel with a Neon Postgres database.

## What it does

- **Syncs runs from Strava** (OAuth) or accepts a CSV import — a run log is the only input required.
- **Computes weekly training load** using the Acute:Chronic Workload Ratio (ACWR, 7-day vs. trailing 28-day mileage) plus the 10% rule, and flags each week as ramp-up / hold / cut-back.
- **Tracks pace trend and aerobic decoupling** by comparing rolling pace and heart-rate cost of pace (beats per mph) week over week, flagging fatigue signals independently of the mileage flag.
- **Writes a narrative log** summarizing the block, this week's call, and next week's recommendations — generated by an LLM that narrates the deterministic numbers (never invents or overrides them), with a template-based fallback if the AI call is unavailable.
- **Lets you set a health baseline** (resting HR, injury history, target race, weekly mileage goal) that feeds into the flags and recommendations.

All of the actual load/pace math lives in [`lib/training/algorithm.ts`](lib/training/algorithm.ts) and is the deterministic source of truth — the AI layer only narrates its output.

## Tech stack

- [Next.js 16](https://nextjs.org) (App Router, React 19, Server Actions)
- [Tailwind CSS v4](https://tailwindcss.com) + [shadcn/ui](https://ui.shadcn.com) components
- [Drizzle ORM](https://orm.drizzle.team) on [Neon](https://neon.tech) serverless Postgres
- [Strava API](https://developers.strava.com) (OAuth) for activity sync
- [Vercel AI SDK](https://sdk.vercel.ai) for narrative log generation
- [Recharts](https://recharts.org) for load/pace charts

## Getting started

### 1. Install dependencies

```bash
pnpm install
```

### 2. Configure environment variables

Create a `.env.local` with:

| Variable | Required | Description |
|---|---|---|
| `DATABASE_URL` | Yes | Neon Postgres connection string. |
| `STRAVA_CLIENT_ID` | Optional | Strava API app client ID — enables the "Connect Strava" flow. |
| `STRAVA_CLIENT_SECRET` | Optional | Strava API app client secret. |

Without a Strava app configured, you can still explore the dashboard by importing a CSV or loading sample data.

### 3. Run the dev server

```bash
pnpm dev
```

Open [http://localhost:3000](http://localhost:3000).

## Desktop app (Electron)

Overreach ships an optional cross-platform desktop app (macOS, Windows, Linux) built with Electron. Because the app is server-backed (Better Auth, Neon, Strava OAuth, server actions, cron), the desktop app is a **remote-URL shell**: it loads your running Next.js server rather than bundling one, so every feature works exactly as it does in the browser.

### Run the desktop app in development

```bash
pnpm electron:dev
```

This starts `next dev` and, once port 3000 is up, opens the Electron window pointed at `http://localhost:3000`.

### Build native installers

1. Set your deployed URL: edit `DEPLOYED_URL` in [`electron/main.js`](electron/main.js) to your production Overreach URL (or pass `ELECTRON_APP_URL` at build time).
2. Build for one or all platforms:

```bash
pnpm electron:build         # current platform
pnpm electron:build:mac     # macOS  → dmg + zip (arm64 + x64)
pnpm electron:build:win     # Windows → NSIS installer + portable exe
pnpm electron:build:linux   # Linux  → AppImage + deb
```

Artifacts are written to `dist-electron/`. Building macOS `.dmg` requires running on macOS; Windows/Linux targets can cross-build from most hosts. Native build config lives in [`electron-builder.yml`](electron-builder.yml), and the app icon is [`build/icon.png`](build/icon.png).

## Mobile apps (Capacitor)

Overreach ships installable **iOS and Android** apps built with [Capacitor](https://capacitorjs.com). Like the desktop app, they are a **remote-URL shell**: the native WebView loads your live deployment (`server.url` in [`capacitor.config.ts`](capacitor.config.ts)), so auth, Neon, Strava OAuth, server actions, and cron all work unchanged. The native projects live in `ios/` and `android/`.

### Set your deployed URL

Edit `DEPLOYED_URL` in [`capacitor.config.ts`](capacitor.config.ts) to your production Stride Log URL (or set `CAP_SERVER_URL` for a staging/LAN build), then push it into the native projects:

```bash
pnpm cap:sync
```

Run `pnpm cap:sync` any time you change the config or update Capacitor plugins.

### iOS (requires macOS + Xcode)

```bash
pnpm cap:sync          # copy config into ios/
pnpm cap:open:ios      # open ios/App/App.xcworkspace in Xcode
```

In Xcode, pick a Simulator or your connected iPhone (set a Team under Signing & Capabilities for a device), then press Run. Capacitor 8 uses Swift Package Manager, so no CocoaPods install is needed.

### Android (requires Android Studio)

```bash
pnpm cap:sync          # copy config into android/
pnpm cap:open:android  # open android/ in Android Studio
```

In Android Studio, let Gradle sync, pick an emulator or connected device, then press Run.

### Testing against a local dev server

Point the apps at your machine instead of production so you can test changes live:

```bash
pnpm dev                                   # start Next.js on :3000
CAP_SERVER_URL="http://<your-lan-ip>:3000" pnpm cap:sync
```

Find `<your-lan-ip>` with `ipconfig getifaddr en0` (macOS). Use the LAN IP (not `localhost`) so the phone/emulator can reach your Mac. `cleartext` is already enabled in the config for http dev servers.

> Note: `ios/` and `android/` are generated by `cap add` and committed to the repo. If they ever go missing, recreate them with `pnpm cap:add:ios` / `pnpm cap:add:android`.

## Data sources

- **Strava** — connect via OAuth; "Sync now" pulls the last ~180 days of runs.
- **CSV import** — columns: `date`, `distance_mi` (or `distance_km` / `distance_m`), `duration` (mm:ss), optional `avg_hr` and `name`.
- **Sample data** — generates a realistic 14-week marathon-build block (including a deliberate overload spike and a taper) to explore the dashboard without connecting real data.

Real data (Strava or CSV) always takes precedence over sample data — if any real runs exist, sample rows are excluded from analysis.

## Project structure

```
app/
  page.tsx              Dashboard (server component)
  actions/               Server actions: activities, log generation, settings, Strava
  api/strava             OAuth authorize/callback routes
components/               Dashboard UI (charts, log panel, data controls, settings form)
lib/
  training/algorithm.ts   Deterministic ACWR + pace/HR flagging (source of truth)
  get-analysis.ts          Loads activities + settings, runs the algorithm
  log-builder.ts           Deterministic Markdown log (fallback narrator)
  strava.ts                Strava OAuth + activity sync
  db/schema.ts              Drizzle schema (activities, settings, log_entries, strava_connection)
```
